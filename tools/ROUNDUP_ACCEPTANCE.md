# 常驻模型与真实验收（2026-10-30）

本轮只完善原综述流程，没有安装依赖、下载模型或重新打包EXE。

## 实际代码改动

- `QwenTTSProvider` 改为窗口持有的单个会话。进程与权重首次真正合成时加载，
  单段试听、后续重试和整稿生成复用；同模型改变说话人/风格不重新加载。
- 工作进程缓存模型，并回传加载次数、状态和请求ID。模型/设备/解释器/权重元数据
  变更前先退出旧进程。增加手动卸载，关闭窗口或主窗口时也释放。
- 使用追加式状态记录，修复Windows中状态文件替换与并发读取的分享冲突。
  推理中取消会终止当前独立进程，等操作系统确认退出才报告停止；下次需要重载。
  两段之间取消只停止后续任务，空闲模型保留，界面如实显示驻留状态。
  已完成音频不删除。生成失败保留可用模型，加载失败清理未就绪进程。
- 文本稿实际调用原API，输入包含程序统计、分组及已有出处短句。程序核验任务ID、
  全部任务覆盖、重点选择、统计原句和引用；不接受新增事实或仅“JSON合法”的输出。
  过渡短句不允许擅自声称“同组/同类”，避免把编辑分组误说成事实关联。
- 缺少配置、请求失败、核验失败使用本期快照的本地模板，明确标为非AI。
  来源及原因写入界面、草稿、Markdown和清单，原因中的密钥会脱敏。
  单段重写保留其他人工编辑，整稿重写仍需明确操作。

`initial-acceptance.json`。实际生成的稿件和数据分别为 `real-draft.json`、
`real-collection.json`，不会改动原Workspace的配置或缓存。

| 验收项 | 结果 |
| --- | --- |
| 使用当前文本配置调用API | 实际调用 DeepSeek / deepseek-flash 成功；通过程序核验并标记 `ai` |
| 本期任务数据 | 北京时间2026-10-23至2026-10-29；授权联网后LL2刷新仍超时，复用工作区旧LL2内容包中的4项记录；没有完整性保证 |

| 真实任务的MOV、清单与稿件 | 实际FFmpeg导出5段PNG MOV，ffprobe核对帧数、文件存在和段落顺序通过；仅用每段2秒的编辑预览时长 |

## 解除阻塞后如何继续

1. 在语音页配置已有的独立Python、完整CustomVoice目录和模型支持的说话人。
   环境安装说明见 [综述说明](ROUNDUP.md)。本轮没有替用户自动安装或下载。
2. 继续使用同一期数据；`tts-sample.txt` 提供专名、LL2缩写和编号的待验文本。
   它只是声学检查，不代表确认旧包的中文译名。真实生成后检查 WAV 样本数和播放。
3. 不卸载模型，连续生成第二段。记录同一工作进程、累计加载次数为1，以及实际
   加载/生成日志；计时与音质结论必须来自这一步的真实运行。
4. 补齐本期任务已核对资料，再检查AI稿件是否足够自然。仅有旧包名称不足以验收
   周总结的背景和重点意义，不应要求模型补写。
5. 全部分段有当前音频后导出完整包，核对清单顺序、WAV样本时长、段间停顿和SRT。
   预览MOV时长不能冒充实际旁白时长。

## Premiere导入检查（仍未验证）

1. 只使用清单 `state=complete` 且 `all_audio_current=true` 的完整配音包，导入旁白WAV、
   分段MOV及 `paragraphs.srt`。保留原成果目录，不覆盖或搬走已引用文件。
2. 建立1920×1080、30fps序列，按清单 `start_seconds/end_seconds` 摆放MOV和旁白。
   分段WAV用于检查，不要和整段旁白同时叠播。检查段间停顿和总时长。
3. 导入段落级SRT，核对段落顺序、中文、编号及字幕起止；不按逐字对齐验收。
4. 播放重点卡片，检查Alpha、正式名称、状态/回收标记、标题遮挡及完整进出场。
5. 试听专名、英文缩写和编号，导出短片复查同步；记录Premiere版本及发现的问题。

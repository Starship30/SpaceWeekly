# 每周发射综述（第一版）

入口：主窗口选择 **每周发射综述 → 配音与画面**。
**完整视频**为默认方案 B。每次导出在所选目录新增一个带音轨的 `SpaceWeekly_YYYY-MM-DD_001.mp4`，字幕内嵌，序号避开已有文件。
在「设置 → 视频输出」切到 **画面素材**，可以从当前稿件逐条导出无声透明 MOV。
画面素材保留任务 ID、独立编号及人工编辑保护，进入时会停止正在播放的旁白。
导出清单用 `audio_policy: silent_no_audio_stream` 明确标记无音轨。
这是可运行的稿件/分段配音/独立画面交付流程，不是自动剪辑器。

## 当前默认画面（2026-11-02 定版）

采用方案 B：左侧分组任务列表，右侧圆角详情卡。右侧显示公司／机构名称，左侧分组不带“方面”；
这只改变画面标签，原有分组身份与口播规则保持不变。载荷独立于任务名称，回收状态仅在适用时显示。

切换时右侧整张卡片向上移出，下一张从下方进入，两张卡片间保留卡高四分之一的距离
（1920×1080 画面为 204 像素）；左侧选框下移。桌面预览与默认导出共用布局和时序。
优先使用当前音频时长，没有当前音频时明确采用预览时长；右侧不叠加字幕。

## 操作顺序

音画同步、讲解单元、独立强制对齐环境及校准操作，见 [音画同步说明](ROUNDUP_SYNC.md)。

1. **日期、任务与统计**：默认按显示时区（初始为北京时间）最近七个完整自然日，不包含今天。
   可修改起止日期，点击 **应用范围（本地）**。打开窗口和编辑不会联网。
2. 数据来自当前 Workspace 的 `cache/launch_collection.json`；旧工作区没有此文件时，
   读取已保存的中文核对资料和输出目录的旧 Premiere 内容包。旧数据没有分页证明，
   明确视为不完整。需要新数据时点击 **刷新 LL2 与资料（联网）**。
   `cache/launch_archive.json` 保留其他日期已读到的原始记录；最新完整范围会替换该范围
   已不再返回的旧条目，历史范围没有最新分页证明时仍按不完整统计。
3. 刷新按相同显示时区范围请求 LL2 detailed 列表，最多20页、每页100条，校验
   count、next 地址、重复 ID、是否读完。后续页失败保留已取得数据并标记不完整；
   首次请求完全失败保留旧缓存。中文核对复用第一部分服务及原网络/AI设置。
4. 勾选、排除任务，调整重点、分组和顺序。重点推荐优先有已核对背景的任务，
   不把“意义重大”当作无来源的推断。机构归属与发射地点国家分开统计，缺失显示未知。
   查看每项 **资料状态**；先点 **补充缺失资料（联网）**，只补本期选中任务的原始说明及出处。
   充分且未变化的资料复用缓存；**重新核对选中任务（联网）** 强制重查一项并保留人工确认。
   旧草稿可用 **同步已保存资料（本地）** 采用新记录；资料操作不改段落，会先留存原稿。
5. **结构化稿件与编辑**：选择60/90/120秒目标，点击 **生成 AI 综述（整稿重写）**。
   该按钮明确替换整稿；只重写选中段不会覆盖其他人工段落。
   可分别编辑口播和屏幕文字、关联任务、调整段落顺序、添加/删除人工段落。
6. **查看任务出处 / 查看段落出处** 显示纯文本引用和快照。缺少任务资料时只使用
   原名，不编造背景。手工修改内容标记为人工编辑，需要自行复核新加事实与出处。
7. **保存草稿** 保存选择、数据快照、段落、语音设置及发音规则；**打开草稿** 比较
   本地最新数据，提示新增/变化/在完整集合中消失的任务，但不替换原快照。
   应用新日期或刷新会新建草稿，请先保存需要保留的稿件。
8. 在 **可选配音、试听与导出** 配置语音，或直接导出稿件。
   选择段落后可试听、强制重生成，或批量生成缺失/过期音频。
   同一窗口的试听与批量生成共用按需加载的模型；可点击 **卸载语音模型** 释放。
9. 在导出页选择输出目录，点击 **导出带配音的 MP4**。工作音频和时间表留在工作区缓存。

统计由程序计算，AI不能更改统计数字或关联不存在的任务。数据不完整或只选择部分
任务时使用“当前收录并选中的任务中”；即使完整，也使用 LL2 收录范围限定，
不把 LL2 等同于绝对无漏项的全球事实。成功/失败/部分失败与回收结果分开计算；
飞行中、载荷已部署等状态不自动等同于已确认成功。历史计划但没有发射证据的任务
归入待确认。统计时点随草稿固定，未来打开不会无声改变已写好的统计。

改变任务选择后，总览的统计指纹会失效，导出/配音会阻止使用旧统计。选择总览并点击
**只重写选中段** 可直接同步程序统计，无需调用AI。人工段落仍需核查自己写的数字。

## 写稿边界

复用原文本服务商、模型、密钥及 API 配置。写稿输入包含程序统计、完整原始说明、
资料状态、可用引文与来源、保留的冲突及分组。自动重点根据资料选择，人工重点保持。
模型组合程序总览、正式名称、有引文的事实转述及简洁过渡语；程序展开为结构化
`spoken` / `screen` / `task_ids` / `source_refs`，校验标记、任务覆盖和人工选择的重点。
引用格式检查后，另用原模型对照原文核查转述；机器支持复核与人工确认分开记录，
不把引文存在视为事实已经成立。LL2说明与主源公告分级，只有LL2时口播必须归因LL2。
资料不足允许写短，不补用途、数量、纪录或意义；来源地址不进入口播或发音替换后的文本。
机器语义复核仍有局限，正式播出前需要人工看出处。见 [资料传递修复及真实验收](ROUNDUP_MATERIALS.md)。
目标时长只是选稿与组织参考；实际时长以 WAV 样本数为准，不自动加速凑时长。

**AI 与模板明确分开**：有文本配置时实际调用原提供商的 API，并输入程序统计、
任务分组、已核对短句及其出处。返回后校验任务ID、覆盖范围、统计原句和正文引用标记，
不是只检查JSON格式。没有凭据、请求失败或输出核验失败时，使用本次真实快照生成
`local_template` 稿，界面、草稿、Markdown和清单保留来源及回退原因，不能称作AI综述。
取消不触发模板回退。只重写一段仍需确认该段的人工编辑，其他段保持原样。
总览减少无意义的零值复述；未确认状态不再读成“实际发射0次”。

## 可选 Qwen3-TTS 环境

语音和文本配置互相独立。优先从 **配音与画面 → 配置语音 → 自动配置** 开始，
无需用户预装 Python 或执行 pip，详见[语音环境自动配置](VOICE_SETUP.md)。
下载只在明确开始配置后进行，不在启动或打开页面时加载模型。
主程序不需要安装 torch/qwen-tts/soundfile；打包只附小型工作脚本及部署清单，环境和权重位于独立用户目录。

“使用已有环境”保留原配置能力。手动维护时可在独立目录建立 Python 环境：

```powershell
python -m venv D:\Tools\spaceweekly-tts
D:\Tools\spaceweekly-tts\Scripts\python.exe -m pip install -r D:\Desktop\SpaceWeekly\tools\requirements-tts.txt
```

请自行通过官方仓库下载完整的
[Qwen3-TTS-12Hz-0.6B-CustomVoice](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice)
模型目录（包括 config、权重、tokenizer、speech tokenizer 等），然后在语音页填写：

- **TTS 环境 python.exe**：上述独立环境的真实解释器。
- **模型目录**：完整本地 CustomVoice 目录。不能填写在线仓库ID以触发下载。
- **说话人**：从当前模型配置读取候选，并在子进程再次校验，如 Vivian。
- **设备**：默认 CPU；CUDA 仅在独立环境具备相应 PyTorch/CUDA 时选择 `cuda:0`。
- **超时**：单段10至3600秒，默认600秒，包含加载模型的时间。
- **风格**：只对配置标明支持指令的1.7B CustomVoice显示；0.6B隐藏。
  官方实现对0.6B忽略 instruct，因此此处不提供误导性的控制。
- **发音替换**：原文与读法的可编辑表格；高级导入导出支持JSON，如 `{"正式名称":"朗读形式"}`。只作用于TTS输入，
  不改变数据、正式屏幕名称或口播稿；不是SSML/音素接口。初始可带入人工确认词典。

点击 **保存独立语音配置** 写入 Workspace `config/roundup_voice.json`。
Base、声音克隆和 VoiceDesign 均不支持。

实现方式是独立常驻 Python 工作进程、UTF-8 JSON请求行、追加式状态记录以及PCM16
单声道WAV结果文件，没有HTTP端口。第一次真正生成时才启动进程、加载模型；
试听后继续批量生成复用同一实例，改变说话人或受支持风格不重载权重。
模型路径、设备、解释器或权重元数据改变时，在下一次生成前先确认旧进程退出，
再加载新实例。手动卸载、关闭综述窗口或退出应用会释放驻留进程。
子进程始终离线加载，使用 `local_files_only` 及 Hugging Face 离线环境变量。

当前适配器使用**进程级取消**：不能假装已经安全中断推理并保留热模型。
推理中取消时界面显示正在终止，确认进程退出后才报告已停止；已成功音频保留，当前临时
文件清理，下次生成重新加载。若操作系统未确认停止，界面保留错误并要求重试卸载。
普通生成失败若模型已加载，则保留实例供重试；加载失败会清理未就绪的进程。
缺环境、依赖、说话人、完整权重或设备时报告实际错误，不返回假音频。

模型与说话人接口依据：[官方Qwen3-TTS代码与说明](https://github.com/QwenLM/Qwen3-TTS)、
[0.6B配置](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice/blob/main/config.json)。

## 音频缓存与成果包

### 可选口播润色

在 **结构化稿件与编辑** 中用 Ctrl/Shift 选择重点或补充段落，点击 **润色选中段口播**。
选段润色只处理重点或补充段落，不重写整稿，不采集新资料。
开头和结尾由程序按范围及统计产生，可主动选择 **只重写选中段** 更新。
沿用当前文本 API，分别进行表达改写与事实保留复核；配置缺失、失败、取消或复核不通过时保留原稿。
来源、数字、载荷数量、用途及不确定性受到检查，机器复核仍需人工查看引文，不能作为官方确认。
已人工修改的选中段会先提示并保存恢复点，未选中段不变；润色期间有新编辑则拒绝覆盖。

编辑器分别保存 **事实原稿**、**屏幕文字**、**最终朗读**。最终朗读留空时沿用原稿。
正式名称来自任务快照和已有确认资料；发音替换仅改变只读预览中的实际 TTS 输入。
原稿或任务/出处关联变化会使润色过期，回退到原稿，并使不匹配的音频过期；已完成文件仍保留。
手工改朗读文字会标为“人工朗读编辑（待复核）”，不继承先前模型的复核结论。

任务表将 **资料准备**、**资料来源**、**独立来源支持**、**人工确认（名称）** 分列。
“已补充资料”表示已有正文；“LL2”表示背景来自 LL2；“原句已匹配”表示外部原句与事件匹配，
不代表全部事实获证实。人工确认单独取自人工记录，缓存命中或模型通过不会自动产生。
悬停状态单元格或查看出处可看到范围、冲突、过期和失败原因。

新增导出文件：`reading_script.md`（完整朗读稿）、`reading.txt`（含替换的最终 TTS 输入）、
`reading_map.json`（按段保存原稿、屏幕、正式名称、朗读/TTS输入、任务与出处关联）、
`material_states.json`（各项资料状态）、`polish_history.json`（存在润色时的前后版本）。
这些信息也进入清单，供后续真实音频对齐使用；本版没有执行逐字对齐。
没有实测音频时只标记“实际口播时长未测量”，不把目标秒数或字数推算当实际时长。

本轮真实口播与回归记录见 [口播验收记录](ROUNDUP_POLISH.md)。

### 国家/公司口播样式

**AI 写作规则 → 每周发射综述** 可编辑整稿、单段重写和选段润色共用的规则；
综述编辑页的 **写作规则** 打开同一个编辑器，支持原有模板保存、导入和导出。
规则变更不自动重写草稿。七天的过去范围默认以“先来看一下过去一周的发射任务。”开头，
其他范围明确起止日期；结尾仅在统计支持时说“本期关注的 N 次发射均取得成功”。

机构按已知国家/公司组织，航天科技集团为“中国方面”，SpaceX 和 Rocket Lab 为美国公司组；
发射地单独取本次记录，同组按实际时间排序。口播省略例行 LL2 归因，但完整出处、任务ID、
争议状态和人工确认状态仍随稿件导出。已知数量必须明说，不能只隐藏在任务名中。
结构化事件与背景引文共同进入模型；另行复核日期/时段、跨日衔接、工位、数量和发射结果。
机器复核不等于人工或独立来源确认。

新读取的 LL2 记录分别保存发射场、工位及机构国家数组；旧快照不自动补写。
旧稿时区与当前显示设置不同时，需显式应用范围新建快照后再写稿。
缺少工位就省略；载荷数量解析只处理明确的 LL2 英文数量格式，其他措辞继续由引文复核，
不从任务编号猜数量。本轮四项任务与具体限制见 [国家/公司样式验收](ROUNDUP_STYLE.md)。

缓存考虑实际送入TTS的文本、模型目录、文件大小/修改时间、说话人、风格、设备、
其他语音设置、发音规则、工作进程脚本及解释器修改时间。正式屏幕文字单独变化
不会使音频过期。更换权重但人为保留所有文件大小/时间，或在同一环境更新依赖时，
请先 **卸载语音模型** 再 **强制重新生成选中段**，本版不逐次计算数GB权重的内容哈希。
音频本身验证格式、样本数和文件内容哈希，损坏文件不会当作当前版本使用。

成功音频放在 `cache/roundup_audio/`；每段完成后将恢复点写入
`output/roundup-drafts/<草稿ID>.json`。失败不影响其他成功段落。单段重写将产生新文本，
不沿用旧音频；重试失败不会覆盖先前的成果目录。

以下是旧版素材包的文件格式，供查看已有成果时参考：

- `draft.json`：可编辑稿件、选择、语音设置和快照，配音路径相对成果目录保存。
- `snapshot.json`、`script.md`：数据快照和方便阅读/编辑的稿件、正式屏幕文字及出处。
- 编号分段 WAV，以及音频全部为当前版本时的整段 `.narration.wav`。
- 可选的 1920×1080 / 30fps PNG RGBA MOV：总览、其余任务简表；重点单任务复用
  原发射卡片并附屏幕标题，多任务重点使用简表。关联的本地素材保留原路径引用，
  不自动下载或搬动源文件。超短画面只压缩卡片动画时间，不加速音频。
- `manifest.json`：段落顺序、任务ID、音频/画面文件、实际音频秒数、起止时间、停顿、
  画面帧数、数据完整性、引用及关联素材。画面按累计音频时长量化至帧，边界误差小于1帧。
- 音频全部齐备时生成 `paragraphs.srt`：有效单元使用单元时间，未对齐部分保留段落级精度；没有逐字动画。
- `timeline.json` 保存实际使用的统一时间表。默认画面导出且配音齐备时，另生成带音轨 MP4。

音频不完整时可以导出已有分段及预览画面，缺音频段使用用户编辑的预览时长，
清单明确标为 `editable_preview`；不生成假旁白或伪精确SRT。采样率不同的分段
在对齐前按同步规则统一为24 kHz PCM16，再以相同采样数拼接。中断的导出保留完成文件，并将清单标为
`incomplete`，请不要把该目录误当完整交付。

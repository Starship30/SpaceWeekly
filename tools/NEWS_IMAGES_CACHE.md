# 新闻图片与缓存维护

资料页的新闻详情提供配图预览、下载 / 重试、候选图选择、本地导入和打开图片文件夹。
原始条目收集时只保留候选，不批量下载待筛选新闻。制作流程筛选完成后为保留新闻下载一张主图；
用户也可在详情中显式下载当前条目的图片。图片失败不会使新闻解析、写稿或配音失败。

候选提取支持 SNAPI `image_url`、条目 `media:content` / `media:thumbnail`、图片 enclosure、
摘要及正文 HTML 的图片。缺少直接字段时复用已取得的原文 HTML，或在下载操作中读取一次有界原文页，
检查 `og:image` / `twitter:image` 和 article/main 中的图片。相对地址以原文 URL 解析，不读取频道 Logo，
不执行脚本、不绕过访问限制。未知署名、许可保持未知。

工作区 `news-images/manifest.json` 用 URL SHA256 新闻身份关联候选、所选图片及其他已收集图片。
图片按完整内容 SHA256 命名，后缀来自解码格式；同一文件可由多个新闻引用，原文标题和地址保留。
通过同一个下载客户端流式取得临时文件，完成解码和大小校验后才原子提交正式文件。
支持 JPEG、PNG、WebP、GIF；最大 24MB、单边 12000、总计 4000 万像素，最小边 32。
连接 / 读取超时 5 / 8 秒，每次最多两次尝试、三次重定向；每条只尝试一个优先候选，用户可切换重试。
原文页上限 2MB。制作与手动图片任务复用原有后台线程、取消机制，最多各一个。

详情缩略图和新闻配音预览均只读取本地图片。原有信息条样式保持；选有配图时把本地图片置于信息条下方，
不更改口播和音频缓存身份。配音视频素材包复制所选图片，便于离线恢复，不因读图隐式联网。
含图视频中的图像区域自然不透明；无图时原有透明信息条行为继续保留。

## 清理

入口为“设置 → 素材与缓存”。提醒周期和保留期分别存于工作区 `config/cache-maintenance.json`，
默认三天。另存检查、提醒、清理、稍后提醒的时间。稍后提醒为次日，关闭期间不会运行服务；
下次启动只检查一次，不补弹多次。没有可清理项目不弹窗，提醒不会自动删除文件。

先检查再按类别选择，真正删除前再次确认，并逐文件复查归属、引用、使用时间、大小和修改时间。
只删除具体文件，不递归删除目录。占用、失败、取消均保留未删文件和原因，仅累计成功删除文件的大小。
已使用的缓存由生产或预览代码记录时间，扫描不更新实际使用时间；旧缓存使用历史未知时先登记观察，
完整等待保留期，不直接把文件修改时间当作最后使用时间。

白名单只包含：

- `cache/news_thumbnails/<sha>.png`：可由正式图片重新生成的缩略图。
- `cache/news_http/<sha>.html`：可重新取得的原文网页副本。
- `cache/news_image_downloads/<uuid>.part`：已结束任务遗留的临时下载。
- `cache/news_pcm`、`roundup_pcm`：已知规范化中间音频及校验信息。
- `cache/news_playback`、`roundup_playback`：已知拼接预览及校验信息。

原始配音、对齐结果、新闻与发射档案、恢复文件、翻译缓存、词典、输出包、正式图片、用户导入文件、
环境、模型和凭据不在清理范围。读取保存稿、历史和输出清单中的文件与音频身份，保护当前引用的中间音频。
运行任务有共享使用保护，播放器来源也纳入保护；清理任务不阻止其他制作任务开始。
符号链接、目录联接、越界路径和未知缓存不处理。引用记录损坏时保守保护，显示提示。

图片候选同时保存在工作区期次和 SQLite；旧表只新增候选列，不重写原有标题或正文。
切换工作区使用各自的图片清单和维护记录。旧期次没有图片字段时仍可恢复。

验证资料见 `build/news-images-20261103/验收记录.md`，真实下载与受控时钟测试分别记录。

# LL2 发射任务中文资料核对

LL2 继续决定发射记录、ID、日期范围、原始时间、火箭、发射场和任务说明。
本功能在内容准备阶段补充有出处的中文名称和简介，不采集独立中文发射事件，
不补入 LL2 漏项，也不涉及视频总结、TTS 或自动剪辑。

## 如何使用与纠错

1. 使用现有中文界面/输出语言，开启航天术语翻译；选择 AI 或混合模式。
   在网络设置中开启联网核对，并选择已有搜索提供商。不会更换 AI 服务商，
   不要求新增付费服务或密钥。Wikipedia 不能用于发射公告核对。
2. 按现有发射日期范围生成内容。任务按 LL2 ID 核对一次，Word、Markdown 和
   Premiere JSON 复用同一份结果。日志逐条列出“发射任务待核对”、ID、原名和原因。
3. 打开 **设置 → 发射任务 → 编辑术语词典...**（原术语编辑器）。下方新增任务表，
   显示 LL2 ID、英文原名、中文名称、简介、资料状态和人工状态。
4. 选择任务，点击 **查看发射资料与出处**：以只读纯文本查看上下文、来源 URL、
   标题、发布时间、检索时间、正文和支持名称/事实/事件时间的逐字引文。
5. 直接修改中文名和简介，再点击 **人工确认任务资料** 即时保存。
   人工结果优先，自动更新不能覆盖；人工确认表示用户已复查，不等于自动证据充足。
6. 点击 **重新核对任务（下次生成）**，下次生成且包含该 LL2 ID 时重新搜索。
   此操作即时保存，不启动阻塞界面的网络请求；需开启上述联网设置。
   自动结果与人工纠正分别保留。LL2 资料变化后，旧人工结果标为待复查，
   在重新人工确认之前继续使用英文原名。

普通术语表中修改并保存的名称也会标记为人工确认；内置默认词条不再覆盖用户修改。
旧词典仍可读，但孤立的旧任务名称不作为“本次发射已确认”的依据。

## 资料与缓存

Workspace 的 `translator/launch_research.json` 按 **原始 LL2 ID** 存储：

- `input`：英文任务名、完整发射名、UTC 原时间、火箭、地点、服务商、任务/载荷说明，
  以及 LL2 的全部 `info_urls` 和 `video_urls`，保持两类列表和原有链接元数据。
- `fingerprint`：上述原始资料的指纹；变化意味着需要重新核对。
- `chinese_name`、`aliases`、`summary`：自动结果；中文简介只摘录公告中的中文原句。
- `sources`：实际读取的正文、来源地址/标题/发布时间/检索时间。
- `matches`：具体名称、别名、简介及对应原句，实际发射时间与事件原句。
- `evidence_status`：`pending` / `supported` / `conflict`；没有模型置信度字段。
- `human_status`、`manual`、`human_fingerprint`：独立的人工确认和纠正，不被模型写入。
- `needs_review`、`recheck_requested`、`reason`：资料变化、重查请求和待核对原因。
- `previous_evidence`：重查前的一版资料，便于追查失败或变更前的名称与出处。

未变化且有证据支持或已人工确认的任务直接复用。缺少出处/状态的旧任务资料与
旧翻译缓存兼容读取，但不自动升级为已确认；普通模型结果写为 `candidate`，
旧记录标为 `unverified`，不会自动写进已确认词典。损坏的资料文件会报错并保留，
不会静默覆盖；本批仍可使用 LL2 原文导出。

## 搜索、匹配与请求成本

复用 `translator.search` 的搜索提供商，先检查本地资料，再将任务名、火箭、日期
组合搜索。英文搜索没有足够事件证据时，使用 UTC+8 日期前后一天、火箭、地点和
机构中文别名查找公告。优先读取 LL2 信息链接及已知官方 HTTPS 域名；范围在
`translator/search.py` 的 `OFFICIAL_DOMAINS` 维护，包含中国航天机构、商业发射服务商
和载荷机构。只有域名匹配不代表事件匹配。

正文读取复用现有公告读取器：校验来源域名、HTML、明确发布时间和正文长度，
正文至多 2 MB，供模型引用的文本至多 7000 字符。重定向页面本轮保留待核对，
避免额外请求和跨站跳转。网页始终作为不可信引用数据，不执行网页指令。

同一事件的自动判定要求：

- 引文中的完整年月日与发射时间相符；明确的北京时间或 UTC/GMT 转换为同一时刻，
  精确时间容差 60 秒。日期相邻只是扩大搜索范围，不能直接证明事件相同。
- 英文任务原名加火箭；无英文原名时，要求火箭、地点、机构加精确时间共同支持。
  只有日期没有时分时，要求任务原名、火箭和地点共同匹配。
- 中文正式名称必须逐字出现在相符事件的正文引文中。别名、简介也必须有原句，
  不能把排名第一、官方域名或模型自评当作证据。
- 普通翻译继续校验数字出现次数、型号和后缀。正式名称只在完整事件对应通过后
  允许数字表达变化，不做全局数字替换；“西光肆号01星”没有内置任务特例。
- 同一事件出现不同名称或可检测的数量冲突时标为冲突；搜索或候选正文失败时
  不标为核对成功。未确认时继续保留 LL2 原名和原说明。

每任务最多 **2 次搜索、4 次正文请求、2 次模型整理**，搜索结果数量同时受原有网络
设置限制。搜索/正文超时沿用设置并上限 15 秒；AI 连接上限 10 秒、读取上限 45 秒，
本核对步骤不自动重试。复用当前 AI 配置，不改变其他 AI 工作流的重试策略。
每次请求前后、正文分块读取时都检查取消；阻塞请求须等待其超时才能返回。

## 导出兼容与边界

Word 和 Markdown 从 `Article.launch_data` 读取准备好的结果；Word 保留旧参数兼容，
但不再在导出器内调用译者。Premiere JSON 保持协议 1.0，发射项增加可选
`launch_context`，里面包含原名、全部资料/视频链接及核对记录；可选
`launch.description_zh` 保存中文简介。稳定素材 ID、`published`、显示时区、状态和
回收字段不变。旧内容包不要求新增字段，离线渲染不联网，不修改原始文件。

这是保守核对：正文缺年、缺时区、无可用机构/火箭别名、网页只靠脚本加载或域名
不在维护列表时，可能保留待核对；人工可添加术语对照或直接确认任务。
简介当前为中文摘录，不对缺少中文来源的英文说明自动扩写。语义上复杂的事实冲突
不能只靠数字比较完全识别，仍需复查出处。此修改没有证明历史翻译失败的唯一原因。
